## 一、项目一句话定位

> 楼宇/医院的数字告示屏，平时循环播放导视图文；一旦按下**应急键**，主屏在人眼察觉不到的时间内整屏切换为疏散指引，提示音与画面同帧起效。整条链路**没有任何处理器**，延迟由时序决定、不随时机波动。

**三个创新点**（答辩主打）：
1. **按键→像素的单帧确定性延迟**（可现场用示波器测量）
2. **多图层像素级并行混合**（图片层 + 文字层 + 音频可视化层，每个像素时钟同步推进）
3. **无处理器架构下的鲁棒性**（硬件 CRC 校验 + 异常自愈，演示"拔卡不断屏"）

## 四、接口契约（冻结）

### 4.1 共享接口 1：图层混合器

**归属**：A 实现并维护。B、C 只提供数据，不改这个模块。

**插入点**：`top_tf_hdmi_audio.v` 第 224 行附近，现在的代码是

```verilog
assign vout_data = display_valid ? vout_data_raw : 24'd0;
```

**改成（示意）**：

```verilog
wire [23:0] vout_mixed;
wire [23:0] scale_rgb;      // B 提供
wire [23:0] text_rgb;       // A 提供
wire [7:0]  text_alpha;     // A 提供
wire [23:0] spec_rgb;       // C 提供
wire [7:0]  spec_alpha;     // C 提供
wire [7:0]  trans_alpha;    // A 提供（转场系数）
wire [7:0]  trans_alpha_inv = 8'd255 - trans_alpha;

layer_mixer u_layer_mixer (
    .clk          (video_clk),
    .rst          (rst_all),
    .x            (pix_x),          // 像素横坐标 0~639
    .y            (pix_y),          // 像素纵坐标 0~479
    .de           (de),
    .base_rgb     (display_valid ? vout_data_raw : 24'd0),
    .scale_rgb    (scale_rgb),
    .text_rgb     (text_rgb),
    .text_alpha   (text_alpha),
    .spec_rgb     (spec_rgb),
    .spec_alpha   (spec_alpha),
    .trans_alpha  (trans_alpha),
    .trans_alpha_inv(trans_alpha_inv),
    .vout_rgb     (vout_mixed)
);

assign vout_data = vout_mixed;
```

**混合规则（按优先级，从低到高）**：

```
第1步（转场）：out1 = (base * trans_alpha_inv + scale * trans_alpha) >> 8
                trans_alpha = 0    → 显示旧图（base）
                trans_alpha = 255  → 显示新图（scale）
                硬切换时直接把 trans_alpha 置 0 或 255，不留过渡

第2步（字幕）：out2 = (out1 * (255 - text_alpha) + text_rgb * text_alpha) >> 8

第3步（频谱）：out3 = (out2 * (255 - spec_alpha) + spec_rgb * spec_alpha) >> 8
```

**模块签名（A 负责建，其他人按此对接）**：

```verilog
module layer_mixer (
    input             clk,              // video_clk 25MHz
    input             rst,
    input      [9:0]  x,                // 0~639
    input      [9:0]  y,                // 0~479
    input             de,
    input      [23:0] base_rgb,
    input      [23:0] scale_rgb,
    input      [23:0] text_rgb,
    input      [7:0]  text_alpha,
    input      [23:0] spec_rgb,
    input      [7:0]  spec_alpha,
    input      [7:0]  trans_alpha,
    output reg [23:0] vout_rgb
);
```

**注意**：全部乘法用 `>>8` 的移位近似（除以 256），**不要引入除法器**，也不要例化 DSP 乘法器之外的东西——LUT 预算要留给缩放。

### 4.2 共享接口 2：参数字典

**归属**：B 实现 `param_regs.v` 并独占写入。A、C **只读**。

| 参数 | 位宽 | 范围 | 默认 | 写入者 | 读取者 | 用途 |
|---|---|---|---|---|---|---|
| `param_brightness` | 8 | 0~255 | 128 | B（拨码1/2） | A（混合器末级） | 亮度加偏置 |
| `param_contrast` | 8 | 0~255 | 128 | B | A | 对比度系数 |
| `param_saturation` | 8 | 0~255 | 128 | B | A | 饱和度（留空则不做） |
| `param_scale_mode` | 2 | 0=自适应 1=铺满 2=1:1居中 | 0 | B | B（自己用） | 缩放模式 |
| `param_transition` | 2 | 0=硬切 1=淡入淡出 2=滑动 3=随机 | 1 | B（key3 循环） | A（转场发生器） | 转场效果选择 |
| `param_dwell_ms` | 16 | 200~10000 | 3000 | B | A（轮播计时） | 停留时间 |
| `param_mode` | 2 | 0=正常 1=应急 2=自检 | 0 | **A（应急键）** | 全员 | 系统模式 |
| `param_viz_en` | 1 | 0/1 | 1 | C（拨码4） | C | 音频可视化开关 |

> **规则**：任何人需要新参数，向 B 提，由 B 加入 `param_regs.v`。**禁止在别处自己声明参数寄存器**，否则会出现"两个真值源"，联调时必翻车。

### 4.3 共享接口 3：音频数据

**归属**：C 使用。数据源来自基线工程现成模块，**不改动源模块**。

```verilog
// 这些信号在 top_tf_hdmi_audio.v 里已经存在，直接引线即可
wire        audio_valid;
wire [23:0] audio_left_data;
wire [23:0] audio_right_data;
```

C 的模块输出：

```verilog
module audio_viz (
    input             clk,              // video_clk
    input             rst,
    input             audio_valid,
    input      [23:0] audio_left_data,
    input      [23:0] audio_right_data,
    // 输出给混合器的图层
    output reg [23:0] spec_rgb,
    output reg [7:0]  spec_alpha,
    // 输出给板上指示（注意：双色 LED 与数码管复用，SW6 只能选一个）
    // led3 = 音频有效指示；数码管低 4 位 = 音频电平
    output reg [7:0]  level_disp
);
```

**C 负责的频谱数据规格**：**8 段**（不是 16 段——LUT 预算留给缩放），每段取值 0~255，用 IIR 滤波器组实现（避免 FFT 占资源）。

### 4.4 共享接口 4：坐标与像素流程

- `pix_x` / `pix_y`：由 A 在 `layer_mixer` 内部用 `de` + 行计数生成，**不对外暴露**。
- 像素时钟：`video_clk` = 25 MHz（`video_pll` 输出）。
- 数据流顺序固定为：**SDRAM 读 → `video_delay`(21拍) → B 的缩放 → A 的混合器 → `video_rgb_to_axis` → HDMI IP**。
- 一行有效区 = 640 像素 @ 25 MHz ≈ 25.6 µs；一帧 ≈ 16.7 ms。

## 五、资源分配表（板上外设，冻结）

### 5.1 按键（4 个，按下为低电平）

**手册第 19 页的官方分配**：`KEY1 = A2`、`KEY2 = B2`、`KEY3 = B1`、`KEY4 = C1`。

**关键事实：板上没有专用复位按键**，基线工程把 `rst_n` 绑在了 **A2（即 KEY1）**。所以：

- **A2 已被 `rst_n` 占用，不可再分配**
- 实际可当"用户按键"的只有 **KEY2 / KEY3 / KEY4 三个**

| 信号名 | 手册引脚 | 归属 | 功能 |
|---|---|---|---|
| `rst_n` | A2（KEY1） | 全员 | 复位（基线工程原有分配，**不要动**） |
| `key1` | B2（KEY2） | A | 手动切下一张；应急模式下切下一条疏散路线 |
| `key2` | B1（KEY3） | A | 自动轮播开 / 关 |
| `key3` | C1（KEY4） | B | 参数调节：进入 / 切换参数项 |
| `key_emergency` | **见下方说明** | A | **应急模式触发键** |

> **⚠️ 移植第一个坑（必读）**：基线工程 `pin.adc` 写的是 `key1 = B2`、`key2 = C1`、`rst_n = A2`。
> 对照手册可知：例程的 `key1` 实际是 **KEY2**，例程的 `key2` 实际是 **KEY4**，而 `rst_n` 占了 **KEY1**。
> **结论**：例程的按键**能用，但名字对不上手册**，而且**只剩 3 个可用按键**。
> **处理方式**：按上表重写，**保留 `rst_n = A2` 不动**，其余三个按键按 KEY2/KEY3/KEY4 分配。

**应急触发键怎么解决（3 个按键不够 4 个用途）**，两个方案：

| 方案 | 做法 | 评价 |
|---|---|---|
| **方案一（推荐）** | 应急触发**改用拨码开关**（如 `sw3`） | 拨码有 4 个、占用少、**状态稳定**，而且测延迟时不用一直按住，示波器单次触发更好抓 |
| 方案二 | 把"自动轮播开关"从按键改到拨码，腾出 `key2` 当应急键 | 改动稍大，需 A 调整状态机输入 |

**无论选哪个方案，必须保留一条"纯电气路径"**：应急信号 → `led4`（B12），供示波器 CH2 探测（见 8.3）。

**约束写法**（B 负责加入 `pin.adc`；`rst_n` 那行保持原样，删掉原有的 `key1`/`key2` 两行）：

```tcl
# rst_n 保持 pin.adc 原有的 { LOCATION = A2; ... } 不动
set_pin_assignment { key1 } { LOCATION = B2; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }  # KEY2
set_pin_assignment { key2 } { LOCATION = B1; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }  # KEY3
set_pin_assignment { key3 } { LOCATION = C1; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }  # KEY4
```

**上板第一件事：逐个按键点一遍**，用 LED 或数码管确认哪个键对应哪个信号。这件事不做，后面所有按键调试都是瞎猜。

### 5.2 拨码开关（4 个，拨上为 1）

| 信号名 | 手册引脚 | 归属 | 功能 |
|---|---|---|---|
| `sw1` | C8 | B | 参数 +（或切换参数项） |
| `sw2` | C7 | B | 参数 − |
| `sw3` | C6 | **A** | **应急模式触发**（方案一；若不采用，则用作转场效果切换） |
| `sw4` | C5 | C | 音频可视化开 / 关 |
| `SW5` | — | 硬件 | 蜂鸣器开关（板上物理开关，与本次设计无关） |
| `SW6` | — | 硬件 | **数码管 / 双色 LED 二选一**（见 5.3 的重要说明） |

约束写法（B 负责加入 `pin.adc`）：
```tcl
set_pin_assignment { sw1 } { LOCATION = C8; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }
set_pin_assignment { sw2 } { LOCATION = C7; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }
set_pin_assignment { sw3 } { LOCATION = C6; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }
set_pin_assignment { sw4 } { LOCATION = C5; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }
```

### 5.3 数码管与双色 LED —— **只能二选一，这是最大的资源陷阱**

板上 **8 位共阳数码管**和 **8 组双色 LED（=16 个 LED）复用同样 16 个 IO**，由 **SW6 乒乓开关**选择：

| 引脚 | 数码管功能 | 双色 LED 功能 | 板上手册引脚 |
|---|---|---|---|
| DIG0 | a 段 | LED6 红 | C15 |
| SEL0 | 第 1 位数选 | LED6 绿 | F16 |
| DIG1 | b 段 | LED7 红 | C16 |
| SEL1 | 第 2 位数选 | LED7 绿 | E16 |
| DIG2 | c 段 | LED8 红 | B6 |
| SEL2 | 第 3 位数选 | LED8 绿 | E12 |
| DIG3 | d 段 | LED9 红 | A5 |
| SEL3 | 第 4 位数选 | LED9 绿 | E10 |
| DIG4 | e 段 | LED10 红 | B5 |
| SEL4 | 第 5 位数选 | LED10 绿 | C13 |
| DIG5 | f 段 | LED11 红 | A8 |
| SEL5 | 第 6 位数选 | LED11 绿 | F10 |
| DIG6 | g 段 | LED12 红 | A7 |
| SEL6 | 第 7 位数选 | LED12 绿 | E11 |
| DIG7 | h/DP 段 | LED13 红 | A6 |
| SEL7 | 第 8 位数选 | LED13 绿 | D11 |

**决策（冻结）**：
- **SW6 拨向数码管**（拨上）：答辩与日常调试用数码管。8 位分配如下：
  - 高 4 位：**B** 显示当前参数值 / 自检状态码
  - 低 4 位：**C** 显示音频电平 / 频谱峰值
  - 段码引脚：`seg_data[7:0]`，位选：`seg_sel[5:0]`（基线工程已约束 6 位：E12/E10/C13/F10/E11/D11）
- **16 个双色 LED**：**在数码管模式下不可用**，只在"LED 演示模式"（SW6 拨下）下作为备用展示手段。**不要把它排进关键验收项**。
- 另有 **4 个独立 LED（LED1=A4, LED2=A3, LED3=C10, LED4=B12）不与数码管复用**，这是**唯一随时可用的状态指示资源**：

| 信号名 | 手册引脚 | 归属 | 功能 |
|---|---|---|---|
| `led1` | A4 | A | 模式指示（正常）/ 应急模式快闪 |
| `led2` | A3 | B | 参数调节激活指示 |
| `led3` | C10 | C | 音频有效指示（有音频流时点亮） |
| `led4` | B12 | **预留** | **延迟测量用**：应急键按下 → 该 LED 翻转（示波器 CH2 探这里） |

**⚠️ A 和 C 的验收项里不要写"双色 LED 显示 XX"**——那是数码管复用资源，答辩现场只能选一个显示。

## 七、工位纪律（只有一块板，必须制度化）

1. **模型文件（`.al`）不进版本管理的冲突区**：由 A 维护一份"标准工程"，B/C 用副本开发，合并时由 A 把源文件挂进去。
2. **仿真优先**：功能正确性在 TD 仿真里验证通过后，才申请上板。
3. **抓波形优先**：调不通先挂逻辑分析仪看内部信号，**不要靠"改一行下载一次"**（一次下载 5~10 分钟，抓波形 1 分钟）。
4. **上板时段登记**：在群公告里贴一张时段表，**每人每次最多占用 2 小时**，超时让给下一位。
5. **备份**：TF 卡至少两张 + 读卡器；工程目录每天下班前拷一份到 U 盘或云盘。
6. **"整屏自测"开关**：每个模块都要做一条"不依赖别人"的验证通道 ——
   - A：拨码进入"字模全字符表"整屏显示

   - C：拨码进入"正弦波测试数据"整屏显示
   这样谁都能独占屏幕自测，不用等别人功能就绪。
