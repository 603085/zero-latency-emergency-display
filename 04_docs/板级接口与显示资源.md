**适用**：HX4S20C（EG4S20BG256）
**配套**：`接口清单_TaskA.md`（模块级接口）、`上板验证清单_TaskA.md`（验证步骤）

# 第一部分：板上显示资源总览

板上**有 4 类显示器件**，很容易搞混。先分清：

| 类型 | 数量 | 引脚 | 受 SW6 影响 | 现状 |
|---|---|---|---|---|
| **8 位数码管** | 8 位 | 16 个（与双色LED复用） | **受 SW6 影响** | 例程用了 1 位 |
| **8 组双色 LED** | =16 个 LED | 同上 16 个 | **受 SW6 影响** | 例程没用 |
| **4 个独立 LED** | 4 个 | A4 / A3 / C10 / B12 | **不受影响** | **例程全空** |
| **4 个按键** | 4 个 | A2 / B2 / B1 / C1 | — | 例程用了 2 个 |

**两条关键结论**：
1. **数码管和双色 LED 是同一组 16 个引脚**，SW6 乒乓开关二选一，**不能同时用**
2. **4 个独立 LED 完全独立**，随时可用，是最可靠的调试资源

## 2.4 8 位数码管（与双色 LED 复用，SW6 二选一）

### 2.4.1 例程的实际情况（先把事实说准）

`seg_sel` 是 6 位，**完全由 `seg_scan` 内部驱动**，与 SD 状态码没有直接关系：

```verilog
// seg_scan.v 内部：按顺序轮流点亮 6 个数码管位（位选低电平有效）
case(scan_sel)
    4'd0: begin seg_sel <= 6'b11_1110; seg_data <= seg_data_0; end  // 第 1 位
    4'd1: begin seg_sel <= 6'b11_1101; seg_data <= seg_data_1; end  // 第 2 位
    ...
    4'd5: begin seg_sel <= 6'b01_1111; seg_data <= seg_data_5; end  // 第 6 位
endcase
```

**SD 状态码只是"往其中一位送数据"**：

```verilog
seg_decoder seg_decoder_m0(.bin_data(state_code), .seg_data(seg_data_0));

seg_scan seg_scan_m0(
    .seg_data_0 ({1'b1,7'b1111_111}),   // 空白
    .seg_data_1 ({1'b1,7'b1111_111}),   // 空白
    .seg_data_2 ({1'b1,7'b1111_111}),   // 空白
    .seg_data_3 ({1'b1,7'b1111_111}),   // 空白
    .seg_data_4 ({1'b1,7'b1111_111}),   // 空白
    .seg_data_5 ({1'b1, seg_data_0})    // 只有第 6 位显示 SD 状态码
);
```

**真实情况：6 位里第 6 位显示 SD 状态码，前 5 位白白空着。**

### 2.4.2 真正的约束：分时复选，不是"驱动源冲突"

```
          ┌──────────────────────────────┐
seg_data ─┤  8 根段线（a~g + DP）         │  ← 所有数码管共用
seg_sel  ─┤  6 根位线（公共端）            │  ← 同一时刻只有 1 位导通
          └──────────────────────────────┘
```

`seg_scan` 就是那个**分时复选控制器**：200 Hz 轮流扫描，每一刻只导通一位，
把对应数据放到共享的 `seg_data` 上。人眼靠视觉暂留看到多位同时亮。

**推论：`seg_data` 是共享总线，同一时刻只能有一个数据源。**
所以想增加显示内容，只有两条路——换掉某个 `seg_data_X` 的内容，或者扩展 `seg_scan`。
**不存在"两个模块各驱动一半"的可能。**

### 2.4.3 三种可行方案

#### 方案 1：利用空白的位（零硬件改动，推荐先做）

前 5 位现在是空的，直接拿来用：

```verilog
seg_scan seg_scan_m0(
    .seg_data_0 ({1'b1,7'b1111_111}),   // 仍空
    .seg_data_1 (param_hi),             // B：参数值高位
    .seg_data_2 (param_lo),             // B：参数值低位
    .seg_data_3 (audio_hi),             // C：音频电平高位
    .seg_data_4 (audio_lo),             // C：音频电平低位
    .seg_data_5 ({1'b1, seg_data_0})    // 保留：SD 状态码
);
```

| | |
|---|---|
| 优点 | **零硬件改动**，只改 `top` 的例化，不碰 `seg_scan.v` |
| 注意 | 6 位位选与物理数码管的对应关系需上板确认 |

#### 方案 2：扩展到 8 位（用满硬件，可选加分）

板上其实是 8 位数码管，例程只用了 6 位：

| 证据 | 内容 |
|---|---|
| `seg_scan` 的 `scan_sel` 是 `reg[3:0]` | 能数到 15，代码却在 `4'd5` 回绕 |
| `pin.adc` 只约束 `seg_sel[0..5]` | **SEL0/SEL1（F16/E16）没约束** |
| 手册 P16~P17 | 明确有 SEL0~SEL7 共 8 位 |

改法：`scan_sel` 改成 0~7 回绕、加 `seg_data_6`/`seg_data_7`、
`pin.adc` 补 F16/E16。

| | |
|---|---|
| 优点 | 8 位全用上，信息量更大 |
| 缺点 | 要改例程的 `seg_scan.v` + 加 2 个引脚约束，风险略高 |

#### 方案 3：数码管只留 SD 状态码，其余全走屏幕

| 数据 | 显示位置 |
|---|---|
| SD 状态码 | 数码管（调试用，保留） |
| **B 的参数** | **屏幕 OSD**（`BRIGHT 136`，有文字更清楚） |
| **C 的音频** | **屏幕频谱条 + LED3 指示** |

| | |
|---|---|
| 优点 | 三方零冲突，不碰数码管，改动最小 |
| 前提 | B 的 OSD 图层 A 已留好（`layer_mixer` 第 4 层，已仿真验证） |

### 2.4.4 分配决定：方案 1 + 方案 3 组合

| 位 | 显示内容 | 归属 |
|---|---|---|
| 第 1 位 | 空 | — |
| 第 2~3 位 | **参数值**（2 位十进制） | **B** |
| 第 4~5 位 | **音频电平**（2 位十进制） | **C** |
| 第 6 位 | **SD 状态码** | A/例程，**保留不变** |

**同时**：B 的参数用**屏幕 OSD 显示完整信息**（`BRIGHT 136` + 进度条），
数码管只做粗显示；C 的频谱在屏幕上，数码管显示峰值数字。

**理由**：数码管只能显示数字，屏幕能显示文字，两者互补——
数码管给运维快速一瞥，屏幕给操作者完整信息。
**方案 1 零硬件改动**（只改 `top` 例化），风险最低。

**实现归属**：`seg_data_1~4` 的合并由 **A 统一在 `top` 里完成**
（`top` 是 A 的集成点），B 和 C 只需各自提供"参数值 / 音频电平"的数值或段码。


## 2.5 双色 LED（8 组 = 16 个）

**建议不使用。** 因为它们和数码管共用引脚，SW6 只能二选一。
演示时数码管更有用（能显示数字），所以 **SW6 拨向数码管**。

# 第三部分：A 的引脚改动汇总（一页速查）

```tcl
# ==================================================================
#  Task A 需要新增/修改的引脚约束
#  追加到 lab_ex5_i2s/src/user_source/constraints_source/pin.adc
# ==================================================================

# ---------- 1. 按键：替换原有的 key1 / key2 两行 ----------
# 手册：KEY1=A2 KEY2=B2 KEY3=B1 KEY4=C1
# rst_n 保持 A2 不动（板上无专用复位键）
set_pin_assignment { key1 } { LOCATION = B2; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }  # KEY2 切图      A
set_pin_assignment { key2 } { LOCATION = B1; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }  # KEY3 轮播      A
set_pin_assignment { key3 } { LOCATION = C1; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }  # KEY4 参数项选择 B

# ---------- 2. 新增：应急触发拨码（A）----------
set_pin_assignment { sw_emergency } { LOCATION = C6;  IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }

# ---------- 3. 新增：参数调节拨码（B，先占位）----------
set_pin_assignment { sw_param_up }   { LOCATION = C8; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }
set_pin_assignment { sw_param_dn }   { LOCATION = C7; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }

# ---------- 4. 新增：音频开关（C，先占位）----------
set_pin_assignment { sw_audio_en }   { LOCATION = C5; IOSTANDARD = LVCMOS33; PULLTYPE = PULLUP; }

# ---------- 5. 新增：4 个独立 LED（例程没有约束过）----------
set_pin_assignment { dbg_latency }   { LOCATION = B12; IOSTANDARD = LVCMOS33; DRIVESTRENGTH = 8; }  # LED4  A
set_pin_assignment { dbg_one_frame } { LOCATION = A4;  IOSTANDARD = LVCMOS33; DRIVESTRENGTH = 8; }  # LED1  A
set_pin_assignment { led_param_act } { LOCATION = A3;  IOSTANDARD = LVCMOS33; DRIVESTRENGTH = 8; }  # LED2  B
set_pin_assignment { led_audio_act } { LOCATION = C10; IOSTANDARD = LVCMOS33; DRIVESTRENGTH = 8; }  # LED3  C
```

**`top` 端口列表要加**：

```verilog
    input  key3,             // C1   参数项选择（B）
    input  sw_emergency,     // C6   应急触发（A）
    input  sw_param_up,      // C8   参数 +（B）
    input  sw_param_dn,      // C7   参数 −（B）
    input  sw_audio_en,      // C5   音频开关（C）

    output dbg_one_frame,    // A4   LED1 延迟合格（A）

```

**`top` 内部（A 的部分）**：

```verilog

assign dbg_one_frame = latency_one_frame;   // 来自 latency_meter
```

**数码管和双色 LED 不需要任何改动**（A 不碰它们）。

# 第四部分：⭐ 参数调节交互设计（方案 1）

## 4.1 为什么需要"选择键"

**B 要调 5 个参数，但只有 2 个拨码。** 引脚不够时用**状态机换引脚**：

```
按 key3（C1）   → 切换"当前在调哪个参数"
拨 sw1（C8）    → 当前参数 +1
拨 sw2（C7）    → 当前参数 −1
```

**2 个拨码 + 1 个按键 = 能调任意多个参数。**

## 4.2 参数项列表

| 序号 | 参数 | 编码 | 显示名 | 归属 |
|---|---|---|---|---|
| 0 | 亮度 | `BRIGHT` | `BRIGHT 128` | B |
| 1 | 对比度 | `CONTRA` | `CONTRA 128` | B |
| 2 | 转场类型 | `TRANS` | `TRANS FADE` | B |
| 3 | 停留时间 | `DWELL` | `DWELL 3000` | B |
| **4** | **配色预设** | **`PRESET`** | **`PRESET 0`** | **A**（并入 B 的参数表） |

## 4.3 操作示例

| 操作 | 数码管/OSD 显示 | 说明 |
|---|---|---|
| 上电 | `BRIGHT 128` | 默认在调亮度 |
| 拨 sw1 几次 | `BRIGHT 136` … `BRIGHT 160` | 亮度上升 |
| 按 key3 | `CONTRA 128` | 切到对比度 |
| 拨 sw2 | `CONTRA 120` | 对比度下降 |
| 按 key3 | `TRANS FADE` | 切到转场类型 |
| 拨 sw1 | `TRANS CUT` | 切成硬切 |
| 按 key3 | `DWELL 3000` | 切到停留时间 |
| 按 key3 | `PRESET 0` | 切到配色预设 |
| 拨 sw1 | `PRESET 1` | 应急配色 |
| 按 key3 | `BRIGHT 128` | 循环回第一项 |

## 4.4 配色预设的 4 种内容（A 提供）

| 值 | 名称 | 文字色 | 底色 | 建议亮度 | 适用场景 |
|---|---|---|---|---|---|
| **0** | 标准 | 白 `#FFFFFF` | 深蓝灰 `#101820` | 128 | 白天正常导视 |
| **1** | 应急 | **红 `#FF3030`** | **白 `#FFFFFF`** | 160 | 疏散指引，远距离高显著度 |
| **2** | 夜间 | 琥珀 `#FFB000` | **纯黑 `#000000`** | **64** | 夜间断电，防眩光 + 省电 |
| **3** | 高对比 | 白 `#FFFFFF` | 纯黑 `#000000` | 200 | 浓烟、低能见度 |

## 4.5 ⚠️ 优先级规则（必须定清楚）

**应急模式会强制覆盖配色预设**：

```
if (mode == EMERGENCY)  →  强制用应急配色（红底/白底高对比），忽略 PRESET 值
else                    →  用 PRESET 选的颜色
```

**理由**：应急时不能因为运维之前把预设调成"夜间"就看不清疏散指引。
**这是安全逻辑，不是用户体验逻辑。**

# 第五部分：A 与 B 的接口（配色预设）

## 5.1 `text_layer` 需要加的端口

现在底色是**编译期参数**（`parameter COLOR_BG`），要改成**运行时输入**：

```verilog
// 新增输入
input [23:0] bg_color,       // 底色，运行时可变（原来 COLOR_BG 是 parameter）
input [1:0]  preset_sel,     // 配色预设 0~3（由 B 的参数寄存器给出）
```

## 5.2 B 需要提供给 A 的信号

```verilog
// B 的 param_regs.v 输出 → A 的 video_layers_top 输入
output [1:0] param_preset;     // 0=标准 1=应急 2=夜间 3=高对比
output       param_preset_en;  // 1 = 用户手动选了预设（优先级低于应急模式）
```

**A 内部的优先级处理**：

```verilog
// 应急模式优先，其次用户预设，最后默认标准
wire [1:0] eff_preset = (mode == 2'd1) ? 2'd1 :          // 应急强制
                        (param_preset_en ? param_preset : 2'd0);
```

## 5.3 A 需要给 B 的反馈

```verilog
// A 内部的状态 → 供 B 的 OSD/数码管显示
output [1:0] cur_preset;       // 当前生效的预设（可能与 param_preset 不同，因为应急会覆盖）
```

**这样 B 的 OSD 能显示"实际生效"的预设，而不是"用户选的"——避免显示与实际不符。**

# 第五部分之二：OSD 图层接口（B 的参数调节条）

## 5b.1 OSD 是什么

**OSD = On-Screen Display，叠加在画面上的信息提示。**
就是电视机调音量时弹出的**音量条**——操作时出现，不操作就消失。

**注意：项目里有两个"叠加文字"，别混**：

| 模块 | 归属 | 内容 | 显示时机 |
|---|---|---|---|
| `text_layer.v` | **A** | 字幕 + 实时计数器 | **常驻**（一直显示） |
| `osd_bar.v` | **B** | 参数调节条 | **按键弹出，2 秒后淡出** |

## 5b.2 图层栈（A 已给 B 留好第 4 层）

`layer_mixer` 现在有 **4 个数据图层**，从下到上：

```
  ① base_rgb / scale_rgb   ← 图片（转场混合）
  ② text_rgb / text_alpha  ← A 的字幕（常驻）
  ③ spec_rgb / spec_alpha  ← C 的频谱
  ④ osd_rgb / osd_alpha    ← B 的参数条（临时）        ← 本次新增
        ↓
  ⑤ brightness / contrast 增强
        ↓
  ⑥ OSD 再叠加一次？不，OSD 在增强之后 ↓
```

**实际顺序（重要）**：

```
图片 → 转场 → 字幕 → 频谱 → 亮度对比度增强 → OSD → 输出
```

## 5b.3 ⭐ 为什么 OSD 放在亮度对比度**之后**

**这是刻意设计的，不是随便放的。**

**问题**：OSD 显示的就是亮度/对比度参数本身。如果 OSD 放在增强**之前**：

```
用户把亮度调到 20  →  OSD 也被压暗  →  正好在最需要看清的时候看不清
```

**解决**：OSD 放在增强**之后**，永远保持原色，不受亮度/对比度影响。

**仿真已验证**：

```
[PASS] mixer: OSD stays full colour at brightness=0 contrast=0
```

**演示话术**：
> "OSD 用来显示亮度参数，所以我们把它放在亮度调节**之后**——
> 用户把亮度调到最低时，参数条依然清晰，不会跟着变暗。"

## 5b.4 B 的 `layer_mixer` 接口

```verilog
// B 的 osd_bar.v 输出 → layer_mixer 输入
input  wire [23:0] osd_rgb,     // OSD 像素颜色
input  wire [7:0]  osd_alpha,   // 0 = 透明, 255 = 不透明（本设计用二值）
```

**和字幕层一样，alpha 是二值的**，所以混合只是一次多路选择，**不额外消耗乘法器**。

## 5b.5 B 的 `osd_bar.v` 要实现什么

| 功能 | 说明 |
|---|---|
| **参数名显示** | `BRIGHT` / `CONTRA` / `TRANS` / `DWELL` / `PRESET` |
| **参数值显示** | `136` / `128` / `FADE` / `3000` / `0` |
| **进度条** | 条形图，直观显示当前值在量程中的位置 |
| **弹出/淡出** | 按 key3 或拨 sw1/sw2 时弹出，2 秒无操作后 alpha 渐变到 0 |
| **位置** | 建议屏幕上方（和 A 的字幕带分开，A 的在下方 y=424/448） |

**可以复用 A 的 `font_rom.v`** 来渲染字符——它是独立模块，A 已经验证过，
B 直接例化即可，不用重新写字模。

## 5b.6 屏幕区域划分建议（避免三方打架）

```
  y=0   ┌────────────────────────────┐
        │                            │
        │      （图片主体）            │
        │                            │
  y=16  │  ┌──────────────────────┐  │
        │  │ BRIGHT      136      │  │ ← B 的 OSD 参数条
        │  │ ████████░░░░░░░░     │  │   （临时，2 秒淡出）
```

# 第七部分：三个最容易踩的坑

## 坑 1：以为数码管和双色 LED 可以同时用

**不行。** 它们是**同一组 16 个引脚**，靠板上 SW6 乒乓开关二选一：
- SW6 拨上 = 数码管工作
- SW6 拨下 = 双色 LED 工作

**演示时只能选一个。建议用数码管。**

## 坑 2：以为 B12 是双色 LED 的一部分

**不是。** B12 = **LED4**，是 **4 个独立 LED** 之一，和数码管**没有共用引脚**，
**不受 SW6 影响，永远可用**。

共用的只有 **LED6~LED13**（8 组双色）↔ **DIG0~DIG7**。

## 坑 3：把 `rst_n` 从 A2 挪走

A2 = 手册的 KEY1，例程用它做 `rst_n`。
**板上没有专用复位按键**，挪走就**失去复位功能**（调试时很致命）。

# 第八部分：v1 → v2 的变更记录

| 项 | v1 | v2 | 原因 |
|---|---|---|---|
| `key3`（C1） | A：切配色预设 | **B：参数项选择键** | 2 个拨码不够调 5 个参数，必须有个选择键 |
| A 的配色预设 | 独立的按键循环 | **并入 B 的参数表（第 5 项）** | 避免 key3 一事两用 |
| A 的 `mode_fsm.key_mode` 端口 | 存在但未使用 | **建议删除或改接 B 的 `param_next`** | 消除死信号 |
| `text_layer.COLOR_BG` | 编译期 parameter | **改为运行时 `bg_color` 输入** | 预设需要运行时换底色 |

# 第九部分：一句话总结

> **A 占 1 个拨码（C6 应急）+ 2 个按键（B2 切图、B1 轮播）+ 2 个独立 LED（B12、A4）。**
> **B 占 2 个拨码（C8/C7）+ 1 个按键（C1 参数项选择）+ 1 个独立 LED（A3）。**
> **C 占 1 个拨码（C5）+ 1 个独立 LED（C10）。**
>
> **key3 不是没功能——它是"参数项选择键"，2 拨码 + 1 按键就能调 5 个参数。**
> **A 的配色预设并入参数表第 5 项，由 B 的参数系统统一管理。**
> **数码管和双色 LED 是同一组引脚（SW6 二选一），建议用数码管。**
