### 1. 上电复位（POR）—— 本次最关键的修复

**症状**：数码管第 6 位（SD 状态码）恒为 `0`，黑屏，按键拨码全无反应，
**但字幕正常**。而且**时好时坏**。

**根因**：

```verilog
assign rst_all = ~rst_n | ~audio_pll_lock;
```

`rst_all` 是**整个设计的复位**，但它**只看音频 PLL 的锁定信号**。
而 `sys_pll` 是**另一个** PLL，它出 100 MHz（给 SD 逻辑）和 125 MHz（给 SDRAM）：

```verilog
sys_pll sys_pll_m0(
    .refclk (clk), .clk0_out (sd_card_clk), .clk1_out (ext_mem_clk), .reset (1'b0)
);                    // ← 锁定信号在 sys_pll.v 里被 .extlock(open) 丢掉了
```

**音频 PLL 一锁，复位就放开了，但 100 MHz 可能还没稳。**
SD 的 CMD 状态机在时钟抖动中跑起来，锁进错误状态、再也回不来 ——
`sd_init_done` 永远不置 1。

视频 PLL 是**第三个**，不受影响，所以字幕照常 —— 这正是这个 bug 难查的地方。

**修法**：加一段**只依赖外部 50 MHz 晶振**的延时。这颗晶振上电就有、
不经过任何 PLL，所以 PLL 再慢它也照样计时。

```verilog
reg [19:0] por_cnt;
always @(posedge clk or negedge rst_n) begin   // clk = 外部 50MHz 晶振
    if (!rst_n)            por_cnt <= 20'd0;
    else if (!por_cnt[19]) por_cnt <= por_cnt + 20'd1;
end
wire por_done = por_cnt[19];                   // 2^20 / 50MHz ≈ 21 ms

assign rst_all = ~rst_n | ~por_done | ~audio_pll_lock;
```

**为什么不直接用 `sys_pll` 的 lock 信号**：`sys_pll.v` 里 `.extlock(open)`
把它丢了，模块没有这个端口；而工程 `.al` 引用的是 `sys_pll.ipc`，
**TD 综合时会按配置重新生成 `sys_pll.v`，直接改生成出来的文件会被覆盖。**

**上板确认**：修好后 A4 亮、B12 闪，数码管走到 2/3/4，出图正常。

### 2. `next_from_current` 位宽 —— 「只显示 4 张图」的根因

**症状**：SD 扫描找到 9 张（第 1 位数码管显示 9），但轮播**只转 4 张**。

**根因**：

```verilog
wire [1:0] next_from_current;                                    // ← 只有 2 位
assign next_from_current = next_index_limited(img_idx, img_found_count);
//                         ^^^^^^^^^^^^^^^^^^ 这个函数返回 4 位
```

**函数返回 4 位，接收的线只有 2 位 —— 高 2 位被无声地截掉了。**

```
next_from_current 只能是 0 ~ 3
        ↓
轮播永远在 0,1,2,3 之间转
        ↓
恰好「4 张工作图」
```

**这是改第 3 项（图数上限扩到 15）时留下的**：`img_idx` / `load_idx` /
`img_found_count` 都扩到了 4 位，**唯独漏了这一根中间信号**。

**修法**：`wire [3:0] next_from_current;`（和函数返回位宽一致）

**为什么原来的回归测试没抓到**：`tb_rot_check` 只观察几秒，轮播本来就没转到 4 以上。
**已补一项专门的检查**：强制 `img_idx = 3`，看下一张算出来是不是 4。
并且**验证过它能抓到这个 bug**（临时把位宽改回 2 位，测试立刻 FAIL）。

> **教训（写给以后）**：扩位宽的时候要把**所有相关信号**一起扫一遍，
> 别只改看得见的那个。也已用脚本全工程扫过一遍，
> 没有别的「函数返回位宽 ≠ 接收位宽」的地方。

### 3. 图数上限：4 张 → 15 张

**原来是五个地方一起卡 4 张**：

```verilog
parameter [2:0] SCAN_TARGET_COUNT = 3'd4;   // 扫描到第 4 张就停
reg [1:0] img_idx;                          // 2 位，最大 3
reg [1:0] load_idx;                         // 同上
reg [31:0] img_sector0..3;                  // 只有 4 个起始扇区寄存器
function [31:0] sector_lut(input [1:0] idx) // 4 项查表
```

**现在全部改成 4 位 / 15 张**：

| 位置 | 现在 |
|---|---|
| `SCAN_TARGET_COUNT` | `[3:0] = 4'd15` |
| `img_idx` / `load_idx` / `img_found_count` / `img_found_o` | `[3:0]` |
| `img_sector0 .. img_sector14` | 15 个 32 位寄存器 |
| `sector_lut` | `input [3:0]`，15 项 |
| 扫描写入的 `case` | 15 项 |
| `bmp_read` 的 `scan_target_count` / `scan_found_total` | `[3:0]` |

**为什么是 15 而不是 16**：4 位能表示的最大值是 15。
`4'd16` 在 4 位里会被**截断成 0**（这个坑踩过，导致扫描计数恒为 0）。
要支持 16 张得把所有相关信号再扩到 5 位，收益不大，**定 15**。

**`next_index_limited` 从 case 表改成了通用公式**，以后不用再改：

```verilog
function [3:0] next_index_limited;
    input [3:0] cur;
    input [3:0] count;
    begin
        if (count <= 4'd2)               next_index_limited = 4'd0;
        else if (cur >= (count - 4'd2))  next_index_limited = 4'd0;  // 折返点 = count-2
        else                             next_index_limited = cur + 4'd1;
    end
endfunction
```

### 4. 应急图 = 卡上最后一张

**需求**：拨上紧急按钮 → 立即切到应急图，而且**平时轮播永远转不到它**。

**实现**：

```verilog
// 折返点 = count-2，所以轮播集合是 0 .. count-2，
// 最后一张（count-1）只能通过应急分支到达
else if (cur >= (count - 4'd2)) next_index_limited = 4'd0;
```

```verilog
// 应急分支放在普通分支【前面】，保证优先级
else if (emg_sel && !load_busy && scan_done
         && (img_found_count > 4'd1)
         && (img_idx != (img_found_count - 4'd1))) begin
    load_idx    <= img_found_count - 4'd1;
    load_sector <= sector_lut(img_found_count - 4'd1);
    ...
    want        <= 2'd0;   // 应急时丢弃排队的切图请求
end
```

顶层：`.emg_sel (layer_mode == 2'd1)`（`MODE_EMERGENCY`，来自图层 FSM）。

> **⚠️ 注意「立即」是分两半的**：
> - **字幕变红是真正的一帧之内**（16.8 ms），拨上开关当场就变
> - **图要等 SD 卡读进来** —— 640×480×24 的 BMP 是 900 KB，
>   SPI 跑 25 MHz，纯数据 0.29 秒，加上开销约 **0.5 秒**
>
> **这是 SD 卡的物理限制，不是逻辑延迟。**

### 5. SD 扫描算法

**原来**：未命中时一次只前进 1 个扇区。

```verilog
assign next_scan_sector_if_miss = scan_sector + 32'd1;   // 慢
```

扫 67 MB（131071 扇区）要 **20 秒** —— 板上表现是「数码管卡在 2、一直黑屏」。

**现在**：

```verilog
assign next_scan_sector_if_match = scan_sector + 32'd8;
assign next_scan_sector_if_miss  = scan_sector + 32'd8;   // 两者相同
```

**为什么一次走 8 个扇区是安全的**：BMP 文件在 FAT32 上必然从**簇边界**开始，
现代 SD 卡簇 ≥ 4 KB（= 8 个扇区），而且簇大小一定是 2 的幂，
**所以所有簇边界都是 8 的倍数**。

**为什么去掉「命中后跳整张图」**：那个跳转（`scan_sector + file_sector_count`）
本身就多跳了 —— `file_sector_count = (921654+511)>>9 = 1801`，
但文件实际只占 225 个簇 = **1800** 个扇区。再向上对齐还可能多跳 7 个。
**只要下一张图的起始位置落在跳转点后面一点，就被永久跳过**
（曾经导致「只找到前 5 张」）。

**去掉跳转后为什么不会误判**：BMP 头判据极严，必须**同时**满足

```
byte[0..1]   = "BM"
byte[18..21] = 640
byte[22..25] = 480
byte[28..29] = 24
```

四个字段全中，在像素数据里凑齐的概率可以忽略，**一张图只会被认出一次**。

**代价与收益**：扫描会走过每张图的内部（每张多约 225 次读），
总读数 `131071 / 8 = 16384` 次，**仍然只要约 2.7 秒**；
换来的是**不管图片怎么排布、间距多少、卡碎不碎，都能找全**。

**`SCAN_MAX_SECTOR` 恢复成全盘 `32'd131071`**（曾经为了治黑屏缩到 32767 = 16 MB，
那是治标，16 MB 以外的图会找不到）。

## 二、⚠️ 资源占用 —— B 和 C 必须先看

### 2.1 数码管（8 位共阳，和 8 组双色 LED **共用同一组 IO，由 SW6 二选一**）

| 位 | 显示内容 | **归属** | 现在接的 |
|---|---|---|---|
| 第 1 位 | 空 | — | ⚠️ **A 临时占用**（`img_found_count`），确认后会还 |
| 第 2 位 | 参数值（十位） | **B** | 空，等 B 接 |
| 第 3 位 | 参数值（个位） | **B** | 空，等 B 接 |
| 第 4 位 | 音频电平（十位） | **C** | 空，等 C 接 |
| 第 5 位 | 音频电平（个位） | **C** | 空，等 C 接 |
| 第 6 位 | SD 状态码 | **A / 例程** | 已接，**保留不变** |

**接线位置**：`seg_data_1` ~ `seg_data_4`（`seg_data_N` 对应第 N+1 位）。

#### ⚠️ 怎么把自己的一位驱动起来（B 和 C 都会用到）

**板子上只有 6 位数码管被扫描**（`seg_scan` 的端口是 `seg_data_0 .. seg_data_5`，
`seg_sel` 是 `[5:0]`）。**第 7、8 位是空的**，接上去也不会显示。

**译码器模块 `seg_decoder`**（`hdl_source\seg_decoder.v`）：

```verilog
module seg_decoder(
    input      [3:0] bin_data,   // 0~9，另外 A~F 也能显示
    output reg [6:0] seg_data    // 共阳，【低有效】
);
```

- `4'd0` -> `7'b100_0000`（g 段灭、其余亮 = 显示 "0"）→ **低有效，共阳**
- 支持 `0~9` 和 `A~F`

**`seg_data_N` 是 8 位**：**最高位是小数点**，低 7 位是 `seg_decoder` 的输出。

**所以接法是**（以 B 的参数值显示到第 2、3 位为例）：

```verilog
// 1) 把参数值拆成十位 / 个位
wire [3:0] param_tens = param_value / 10;
wire [3:0] param_ones = param_value % 10;

// 2) 各接一个译码器
wire [6:0] seg_tens, seg_ones;
seg_decoder u_seg_param_tens (.bin_data(param_tens), .seg_data(seg_tens));
seg_decoder u_seg_param_ones (.bin_data(param_ones), .seg_data(seg_ones));

// 3) 顶层 seg_scan 实例里替换掉那两行占位
.seg_data_1  ({1'b1, seg_tens}),   // 第 2 位：参数十位
.seg_data_2  ({1'b1, seg_ones}),   // 第 3 位：参数个位
```

> **`{1'b1, ...}` 里的 `1'b1` 是小数点，填 1 = 灭。** 要显示小数点就填 `1'b0`。
> 现在那几行占位写的是 `{1'b1,7'b1111_111}`（7 位全 1 = 全灭 = 整位不亮）。

**C 的第 4、5 位同理**，把上面的 `param_value` 换成音频电平即可。

**示例已经在本工程里跑着** —— A 的第 6 位就是这么接的：

```verilog
wire [6:0] seg_data_0;
seg_decoder seg_decoder_m0 (
    .bin_data  (state_code),      // 4 位 SD 状态码
    .seg_data  (seg_data_0)
);
// ...
.seg_data_5  ({1'b1, seg_data_0})   // 第 6 位
```

**第 6 位的含义**（A 保留，排查 SD 问题时很有用）：

| 码 | 含义 |
|---|---|
| **0** | SD 卡**没初始化成功**（`sd_init_done = 0`）—— 查卡座接触、卡是不是在电脑上动过 |
| 1 | 空闲，等扫描或装载 |
| **2** | **正在扫描扇区**（正常持续约 2.7 秒）/ 正在读文件头 |
| 3 | 文件头 OK，等写请求 |
| 4 | **正在读像素数据** |

**正常上电顺序：`0 → 2 → 3 → 4 → 出图`。**

## 三、SD 卡放图规则（这次变了，请重新看）

### 3.1 张数与顺序

```
0  … 13   平时轮播（最多 14 张）
14        应急图（必须是最后一张）
```

- **最多 15 张**（前 14 张轮播 + 最后 1 张应急）
- **应急图必须是最后一张**，轮播按 `count-2` 折返，永远转不到它
- 张数少于 15 也可以，只要应急图在最后

### 3.2 ★ 换图必须「格式化 → 按顺序拷贝」

**`bmp_read` 是读【原始扇区】的，不认文件系统。** 由此有两条硬规则：

**① 不要单独删某张图。**
删文件**不会擦掉数据**，那些簇只是被标记为空闲，**内容还在盘上**，
扫描器照样能读到它、并把它当成一张图。
（实测过：删掉文件后，磁盘上文件 9 个，但原始扇区里能找到 10 个 BMP 头。）

**② 不要单独往里加图。**
FAT 可能把新文件分配到别处，**物理顺序就乱了**，应急图可能混进轮播。

**正确做法**：

```
格式化（FAT32） -> 按顺序整套拷进去
```

**已经写了个工具** `04_工具\verify_usb_order.py`：
逐个字节比对扇区内容和文件，能提前发现顺序错乱和残留。
`04_工具\make_bmp.py` 负责把 PNG 转成 640×480 24 位 BMP。

### 3.3 BMP 格式要求（不满足就整张不显示）

```
文件头必须是 "BM"
宽 640   高 480   位深 24        ← 必须是 24 位
```

**Photoshop 默认存 32 位，读不出来，要注意。**

### 3.4 ★ 卡在电脑上动过之后，板子必须【断电重上电】

**按复位键（KEY1/A2）不管用** —— 它只复位 FPGA 逻辑，
**SD 卡自己不掉电，通信模式不变。**

SD 卡有 SD 原生模式和 SPI 模式两种，模式在上电那一刻确定、
**一直保持到断电为止**。电脑/读卡器用 SD 原生模式初始化这张卡之后，
卡会**忽略 SPI 命令**，板子就再也初始化不了它。

```
正确做法：拔掉电源 / 拔掉 USB 线 -> 等 5 秒以上 -> 卡插着，再上电
```

### 4.1 现在的音频通路

```
PLL_HDMI_AUDIO (12.288 MHz)
        ↓ audio_mclk
hdmi_audio_tone_i2s_64fs          ← 自生成音阶：do re mi fa so la si do
        ↓ audio_i2s_bclk / audio_i2s_lrck / audio_i2s_dout
I2S_receiver                      ← 回环接收
        ↓ audio_valid / audio_left_data[23:0] / audio_right_data[23:0]
hdmi_1_4b_transmitter_core_wrapper
        ↓
HDMI 音频
```

**现在只有一个音源**，`hdmi_audio_tone_i2s_64fs` 循环播放 8 个音，
每个音保持 0.5 秒（`NOTE_HOLD_FRAMES = 24000 @ 48 kHz`）。

### 4.2 需求

| 模式 | 期望 |
|---|---|
| **平时**（`sw_emergency = 0`） | 工作音频 —— 平缓、不吵人 |
| **应急**（`sw_emergency = 1`） | 应急音频 —— 一听就知道出事了，要能引起注意 |

**切换要「拨上就换」** —— 不要等到当前这个音放完。

### 4.3 接口设计建议

**给 `hdmi_audio_tone_i2s_64fs` 加一个模式输入**：

```verilog
module hdmi_audio_tone_i2s_64fs #(
    parameter [31:0] PHASE_INC = 32'd39370534,
    parameter signed [23:0] AMP = 24'sd2000000,
    parameter integer NOTE_HOLD_FRAMES = 24000
)(
    input  wire I_mclk,        // 12.288MHz
    input  wire I_rst,
    input  wire I_emergency,   // ★ 新增：1 = 应急音频
    output reg  O_i2s_BCLK,
    output reg  O_i2s_LRCK,
    output reg  O_i2s_DOUT
);
```

**顶层接法**（`sw_emergency` 已经在顶层，直接用）：

```verilog
hdmi_audio_tone_i2s_64fs #(
    .PHASE_INC (32'd39370534),
    .AMP       (24'sd2000000)
) u_hdmi_audio_tone_i2s_64fs (
    .I_mclk      (audio_mclk),
    .I_rst       (rst_all),
    .I_emergency (sw_emergency),   // ★ 拨上 C6 立即切应急音频
    .O_i2s_BCLK  (audio_i2s_bclk),
    .O_i2s_LRCK  (audio_i2s_lrck),
    .O_i2s_DOUT  (audio_i2s_dout)
);
```

> **也可以用 `layer_mode == 2'd1`**（图层 FSM 的 `MODE_EMERGENCY`）代替
> `sw_emergency`，两者一致。用 `sw_emergency` 更直接、延迟更小。

**内部实现的两个要点**：

1. **平时**：沿用现在的音阶，或者改成更平缓的单音 / 慢速提示音
2. **应急**：换成高急促的报警音。最典型的是**两个音快速交替**
   （类似消防警报），比如 A5 ↔ E5，**交替周期 0.25 秒左右**
   —— 也就是把 `NOTE_HOLD_FRAMES` 在应急时改小

   ```verilog
   wire [15:0] hold = I_emergency ? 16'd12000 : NOTE_HOLD_FRAMES;  // 应急快一倍
   ```

   **注意 `I_emergency` 必须参与音阶索引的复位或强制跳转**，
   否则拨上开关后要等当前那个音放完才换 —— 那就不叫「拨上就换」了。

**`AMP` 也可以分开**：应急时响一点。但**注意 HDMI 音量是数字域**，
调太大直接削顶失真，建议应急不超过平时的 1.5 倍。

### 4.4 注意：这个改动只动音频，不影响别的

- **不需要动 `I2S_receiver` 和 HDMI 发送器** —— 它们只负责搬数据
- **不需要动 `audio_mclk` / PLL** —— 采样率和时钟不变
- **不需要新的引脚** —— `sw_emergency` 已经在用了
- **`led_audio_act`（C10）现在是写死 `1'b0` 的钩子**，
  正好可以拿来指示「音频有效」，顶层里改掉那一行即可

### 4.5 验收标准建议

```
1. 平时上电    -> 听到工作音频，平缓
2. 拨上 C6     -> 【立刻】变成应急音频，不等当前音放完
3. 拨下 C6     -> 【立刻】变回工作音频
4. 反复快速拨动 -> 不卡死、不出现持续静音
5. 应急时字幕变红（A 的部分）和音频切换【同时】发生
```

### 5.3 时序（TD 报告，实测）

| 时钟域 | WNS | 失败端点 | 说明 |
|---|---|---|---|
| `video_clk` | **+4.097 ns** | 0 | 干净 |
| `sd_card_clk` | **−0.305 ns** | 2 | 路径在 `bmp_read` 的 `file_len → state`（装载比对），**原设计路径** |
| `ext_mem_clk` | **−0.271 ns** | 4 | TNS −0.612 |
| `clk → audio_mclk` | **−2.959 ns** | 48 | **跨时钟域路径，约束没写**（见下） |

**关于 `clk → audio_mclk` 那 48 个端点**：
这是 50 MHz 的 `clk` 到 12.288 MHz 的 `audio_mclk` 的**跨时钟域路径**，
工具把它**当同步路径**在算，所以算出个巨大的"违规"。
**这不是逻辑问题，是约束没写** —— 跨时钟域路径应该声明成异步 / 假路径。

> **⚠️ 待办**：需要确认那两个时钟域之间**有没有正确加两级同步器**。
> 如果没有，那是**真实的亚稳态隐患**，会造成偶发故障。**这一项还没查，列在待办里。**

**关于 `sd_card_clk` 那 2 个端点**：
路径是 `file_len_reg → state_reg / state_code_reg`，即 `bmp_read` 里
`bmp_len_cnt >= file_len` 的 32 位比较器（9 级逻辑）。**这是原设计的路径，
本次改动没有加重它。** 余量 −0.305 ns 偏小，温度和电压一变就可能翻车，
**建议后续把那个比较器改成分段比较或加流水**。
